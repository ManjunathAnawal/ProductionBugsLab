# C30: Crash log with only hex addresses

**Family:** Ward 9: Release and tools (real phone)  
**Severity:** Medium

## Field report

> A TestFlight crash shows only hex addresses. Nobody can read it.

## 1. Reproduce

Use a real device. Product > Archive (Release). Install it. Tap Crash for symbolication practice. Get the crash log: Xcode > Window > Devices and Simulators > View Device Logs.Then match the UUID and symbolicate.

## 2. Tools to try

- Window > Devices and Simulators > View Device Logs
- dwarfdump --uuid
- atos
- Xcode Organizer > Crashes

## 3. Where the bug lives

- `TriageLab/Logic/L30_SymbolPractice.swift`

> Tip: do not open these files yet. Reproduce and investigate first.

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- Without the dSYM for that exact build, addresses cannot be turned into names.
- The crash is `values[5]` on an empty array, three functions deep.

### How to prove it

- `atos` prints `SymbolPractice.readLastValue(_:)` and the line, then `buildSection` and `startReport`.
- Organizer shows the same stack, readable, if the dSYM is available.

### Fix

```swift
# In CI after every release archive:
# 1. keep the .xcarchive (it holds the dSYMs)
# 2. check the UUIDs
dwarfdump --uuid TriageLab.app.dSYM

# 3. upload the dSYM to your crash tool
# 4. fail the build if the upload fails
```

### Prevent it next time

- Upload the dSYM for every build in CI.
- Keep the archive for every build number.

### One-line summary

Missing dSYM means hex stacks. I match UUIDs with dwarfdump, symbolicate with atos, and automate the upload in CI.

</details>
