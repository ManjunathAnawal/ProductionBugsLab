# C18: Patient got two refill orders

**Family:** Ward 4: Network  
**Severity:** Critical

## Field report

> A patient received two refills after one nervous double tap.

## 1. Reproduce

Tap Order refill twice quickly. Read the message.

- Console (order_submit, order_created)
- Breakpoint in submit

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- The button is never disabled. There is no idempotency key. The server creates one order for every request.

### How to prove it

- Log: two `order_submit`, then `order_created` order=1 and order=2.

### Fix

```swift
// App: disable the button while sending, and send ONE key per order.
var request = URLRequest(url: url)
request.httpMethod = "POST"
request.setValue(orderID.uuidString, forHTTPHeaderField: "Idempotency-Key")

// Server: if the key was seen, return the first result.
```

### Prevent it next time

- Idempotency key on every request that creates something.
- Disable buttons while a request runs.

### One-line summary

Duplicate orders: no idempotency key. Same key on every retry, server dedupes, button disabled while sending.

</details>
