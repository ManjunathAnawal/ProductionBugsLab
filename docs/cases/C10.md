# C10: Crash: incorrect actor executor

**Family:** Ward 2: Crashes  
**Severity:** High

## Field report

> Crash after refreshing from the bedside device. Message mentions an actor executor.

## 1. Reproduce

Tap Refresh from device.

## 2. Tools to try

- Xcode stack trace
- Console message

## 3. Where the bug lives

- `TriageLab/Logic/L10_Bedside.swift`

> Tip: do not open these files yet. Reproduce and investigate first.

## Hints (one at a time)

</details>

<details><summary>Hint 2</summary>

</details>

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- The old API calls back on a background queue.
- The code uses `MainActor.assumeIsolated`. It promises 'I am on main'. The promise is false, so the app traps.

### How to prove it

- Console: Incorrect actor executor assumption. The stack shows the background queue.

### Fix

```swift
LegacyDeviceApi.fetch {
    Task { @MainActor in
        model.markUpdated()
        onDone()
    }
}
```

### Prevent it next time

- Do not use `assumeIsolated` as a shortcut.
- Fix the caller. Hop to the main actor properly.

### One-line summary

assumeIsolated is a check, not a hop. The callback was on a background queue. I used a MainActor task.

</details>
