# C14: First screen takes 10 seconds

**Family:** Ward 3: Hangs, launch, speed  
**Severity:** Critical

## Field report

> After enabling Slow start-up, the first screen takes more than 10 seconds. On real phones iOS closes the app at launch.

## 1. Reproduce

Turn on Slow start-up. Stop. Run again and time the first screen.To recover: Edit Scheme > Run > Arguments > add -fixSlowLaunch.

## 2. Tools to try

- Console (startup_config_fetch_begin / end, time_to_first_screen)
- Xcode Pause during launch
- Instruments: App Launch

## 3. Where the bug lives

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- Start-up code waits on a semaphore for a fake server reply, on the main thread, before the first screen.
- On a real phone the watchdog kills the app (about 20 seconds). It is not enforced in the Simulator or with the debugger.

### How to prove it

- Console: `time_to_first_screen` is more than 10000 ms.
- Pause: main thread in `semaphore_wait`, called from `AppBootstrap.start`.

### Fix

```swift
// 1. Show the first screen first.
// 2. Load config later, with a short timeout and a cached default.
Task {
    let config = await ConfigLoader.loadWithTimeout(seconds: 3)
    apply(config)
}
```

### Prevent it next time

- Launch never waits for the network.
- Budget for time to first screen in CI.

### One-line summary

Launch waited on the network. I showed the first screen first, loaded config later with a timeout, and used cached defaults.

</details>
