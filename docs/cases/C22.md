# C22: Negative minutes around the clock change

**Family:** Ward 5: Data, time, location

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- Readings are saved as local time text. The hour from 1:00 to 2:00 happens twice that night.
- '01:20' can mean two different moments. The app picks one and the order breaks.

### How to prove it

- Report shows 01:50 -> 01:20 as -30 min. The real gap is +30 min.

### Fix

```swift
// Store UTC (ISO 8601 with offset). Show local time only on screen.
let formatter = ISO8601DateFormatter()
let saved = formatter.string(from: Date())          // 2026-11-01T05:20:00Z
let date = formatter.date(from: saved)

// Use a monotonic clock for durations on the device.
```

### Prevent it next time

- Never store local time text.
- Test around DST changes.

### One-line summary

Local time strings are ambiguous during the DST fall-back hour. Store UTC with offset, display local.

</details>
