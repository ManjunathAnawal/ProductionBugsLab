# C06: Crash after going back quickly

**Family:** Ward 2: Crashes  
**Severity:** High

## Field report

> Crash a few seconds after a nurse opens the lab result and goes back.

## 1. Reproduce

Open lab result. Tap Load. Go back within 3 seconds. Wait.

## 2. Tools to try

- Xcode stack trace
- Console message
- Log (slow_load_start / slow_load_done)

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- The closure waits 3 seconds. It captures `self` as `unowned`.
- The screen closed, so the loader was freed. When the closure runs, `self` is gone and the app traps.

### How to prove it

- Console: Attempted to read an unowned reference but object was already deallocated.
- Log has `slow_load_start` but no `slow_load_done`.

### Fix

```swift
DispatchQueue.main.asyncAfter(deadline: .now() + 3) { [weak self] in
    guard let self else { return }
    self.result = "loaded"
    self.onDone?()
}
// or cancel the work in deinit
```

### Prevent it next time

- Use `weak` for work that can outlive the screen.
- Cancel pending work when the screen goes away.

### One-line summary

A delayed closure used unowned self and the screen was gone. Fix: weak self with a guard, and cancel the work.

</details>
