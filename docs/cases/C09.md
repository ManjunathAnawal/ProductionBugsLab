# C09: Wrong count, sometimes a crash

**Family:** Ward 2: Crashes  
**Severity:** High

## Field report

> The reading count is sometimes lower than expected. Rarely the app crashes with a malloc error.

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- `concurrentPerform` runs many threads. They all call `values.append` on one array without a lock. This is a data race.

### How to prove it

- Thread Sanitizer: Data race detected (Issue Navigator). Two threads write the same address. It reports this on every run.
- Without the Sanitizer the count may look right on some runs. On a Mac with many cores it is often lower, and sometimes the app crashes. A race does not fail every time. That is why it is dangerous.

### Fix

```swift
final class ReadingBuffer {
    private let queue = DispatchQueue(label: "readings")
    private var values: [Int] = []

    func add(_ value: Int) {
        queue.sync {
            values.append(value)
        }
    }

    var count: Int {
        queue.sync {
            values.count
        }
    }
}
```

### Prevent it next time

- One owner for shared data: a lock, a serial queue, or an actor.
- Run Thread Sanitizer in CI.

### One-line summary

Random wrong counts and malloc crashes mean a data race. Thread Sanitizer pointed at the array. I gave the data one owner.

</details>
