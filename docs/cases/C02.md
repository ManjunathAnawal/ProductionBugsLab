# C02: App closes on the photo gallery

**Family:** Ward 1: Memory and silent kills  
**Severity:** Critical

## Field report

> Nurses on older iPhones say the app closes by itself when they open the scan gallery. Our crash tool shows nothing.

## 1. Reproduce

Set Photos to 8, tap Load photos. Watch memory.Raise to 24 and load again. On a real iPhone iOS will close the app. Reopen it and open the Black Box screen.

## 2. Tools to try

- Xcode Memory gauge
- Instruments: Allocations + VM Tracker
- Black Box: last-run report
- Xcode Organizer > Terminations (real apps)

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- Each photo is decoded at full size: 4032 x 3024 x 4 bytes is about 48.8 MB.
- All photos are kept at once. 24 photos is about 1.1 GB. iOS closes the app when it passes its memory limit. No crash report is made.

### How to prove it

- Memory gauge jumps by about 49 MB per photo.
- Instruments > Allocations: big `[UInt8]` buffers. VM Tracker shows dirty memory growing.
- Real phone: after the kill, Black Box says `unknown_in_foreground` with the last memory numbers. The log has `silent_end_suspected`.

### Fix

```swift
// Do not decode full size. Make a small thumbnail with ImageIO.
let options: [CFString: Any] = [
    kCGImageSourceCreateThumbnailFromImageAlways: true,
    kCGImageSourceThumbnailMaxPixelSize: 600,
    kCGImageSourceCreateThumbnailWithTransform: true
]
let thumbnail = CGImageSourceCreateThumbnailAtIndex(source, 0, options as CFDictionary)
// Keep only the visible photos. Load 2 or 3 at a time.
```

### Prevent it next time

- Check memory left before heavy work.
- Test with 50 photos on the oldest phone.
- Alert on `unknown_in_foreground` per app version.

### One-line summary

No crash report means iOS closed it. I read the last-run log, did the memory math (48 MB per decoded photo), and fixed it by downsampling.

</details>
