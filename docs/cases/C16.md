# C16: Expanded rows close by themselves

**Family:** Ward 3: Hangs, launch, speed  
**Severity:** Medium

## Field report

> Rows that a nurse expands close again after one second.

## 1. Reproduce

Tap Patient 2 to expand. Watch for a second.

## 2. Tools to try

- let _ = Self._printChanges() in body
- Instruments: SwiftUI
- Breakpoint in the rows property

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- `rows` creates new rows with `UUID()` as the id every time `body` runs. SwiftUI sees brand-new rows, so the `@State isOpen` resets.

### How to prove it

- Add `let _ = Self._printChanges()` to `body`: it re-runs every second.
- Print `rows.map(\.id)`: different on every tick.

### Fix

```swift
private let rows: [RowItem] = (1...5).map { number in
    RowItem(id: number, title: "Patient \(number)")   // stable id
}
// RowItem.id is now an Int.
```

### Prevent it next time

- Use stable ids.
- Keep model data in state, not rebuilt in body.

### One-line summary

Unstable identity. New UUIDs each render made SwiftUI rebuild rows and reset state. Stable ids fixed it.

</details>
