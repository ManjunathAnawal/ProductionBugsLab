# C27: Heart rate frozen but 'Connected'

**Family:** Ward 7: Bluetooth (fake band)  
**Severity:** Critical

## Field report

> The heart rate on screen froze at one number while the status still says Connected.

## 1. Reproduce

Tap Connect. Watch for 20 seconds. The fake band drops the link at 6 seconds.

## 2. Tools to try

- Console filter: ble
- Breakpoint in didConnect
- Reading: what resets on disconnect?

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- The link is lost and the band forgets the subscription.
- The app reconnects but subscribes only the first time. No new readings arrive. The screen keeps showing the old number as if it were live.

### How to prove it

- Log: one `ble_subscribe`, then `ble_link_lost`, then `ble_connected` and no second `ble_subscribe`.
- Screen shows the same bpm while status says Connected.

### Fix

```swift
func central(didConnect peripheral: FakePeripheral) {
    onStatus?("Connected")
    peripheral.subscribeToHeartRate()          // EVERY connect, not only the first
}

// UI: keep a timestamp for each reading.
// If it is older than 5 seconds: grey it out and show 'NO SIGNAL'.
```

### Prevent it next time

- Subscribe again after every reconnect.
- Never show an old reading as live.
- Alarm on no signal.

### One-line summary

After reconnect the subscription was gone. I subscribed on every connect and added a freshness label so old readings cannot look live.

</details>
