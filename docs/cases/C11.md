# C11: Crash at every launch after a download

**Family:** Ward 2: Crashes  
**Severity:** Critical

## Field report

> After tapping 'Download new config', the app crashes at every launch. Reinstall fixes it.

## 1. Reproduce

Tap Download new config. Stop the app in Xcode. Run again.To recover: Edit Scheme > Run > Arguments > add -resetLabConfig.

## 2. Tools to try

- Xcode stack trace at launch
- Console
- Window > Devices and Simulators > Download Container

## 3. Where the bug lives

- `TriageLab/Logic/L11_ConfigStore.swift`
- `TriageLab/App/AppBootstrap.swift`

> Tip: do not open these files yet. Reproduce and investigate first.

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- The server wrote `"refreshSeconds": "fast"` (text, not a number).
- `ConfigStore.load()` uses `try!`. It crashes on every launch, so the app cannot start. This is a crash loop.

### How to prove it

- Xcode: Fatal error: 'try!' expression unexpectedly raised an error: typeMismatch(Int...).
- Device container > Library/Caches/lab-config.json shows the bad value.
- Black Box (after recovery): last run is `unknown_in_foreground` several times in a row.

### Fix

```swift
static func load() -> LabConfig {
    guard let data = try? Data(contentsOf: url) else { return .defaults }
    do {
        return try JSONDecoder().decode(LabConfig.self, from: data)
    } catch {
        Log.error(.lifecycle, "config_bad_deleted")
        try? FileManager.default.removeItem(at: url)   // delete the bad file
        return .defaults
    }
}
// Also: crash loop breaker. After 3 bad launches in a row start in safe mode.
```

### Prevent it next time

- Never `try!` on data from disk or network.
- Safe defaults. Crash loop breaker.
- Validate config before saving it.

### One-line summary

A crash at launch every time: bad config on disk plus try!. I read the file from the device container, fixed the decode with safe defaults, and added a crash loop breaker.

</details>
