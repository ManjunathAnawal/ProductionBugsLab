# C03: Memory grows all day on the live feed

**Family:** Ward 1: Memory and silent kills  
**Severity:** High

## Field report

> Charge nurses keep the live feed open all shift. After a few hours the app closes.

## 1. Reproduce

Tap Refresh live feed 20 times. Watch the memory numbers go up in steps.

## 2. Tools to try

- Xcode Memory gauge
- Instruments: Allocations (Mark Generation)
- VM Tracker

## 3. Where the bug lives

- `TriageLab/Logic/L03_FeedCache.swift`

> Tip: do not open these files yet. Reproduce and investigate first.

## Answer

<details><summary>Show the answer (try first!)</summary>

### Root cause

- Each refresh saves 3 MB under a new key (the key has the time in it). Nothing is ever removed.

### How to prove it

- Allocations > Generations: each refresh adds about 3 MB that stays alive.
- Memory gauge is a staircase.

### Fix

```swift
private let cache = NSCache<NSString, NSData>()

init() {
    cache.countLimit = 20
    cache.totalCostLimit = 30_000_000
}

func save(_ data: Data, for key: String) {
    cache.setObject(data as NSData, forKey: key as NSString, cost: data.count)
}
```

### Prevent it next time

- Every cache needs a size limit.
- Clear caches on memory warning and when the app goes to background.

### One-line summary

A staircase memory curve points to an unbounded cache. I used Mark Generation to see what survives each refresh.

</details>
